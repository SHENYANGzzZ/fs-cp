# Trae 项目规则

<br />

## 2. 代码规范

### 2.1 编码风格

- 命名规范：
  - 变量/函数：camelCase
  - 类/接口：PascalCase
  - 常量：SNAKE\_CASE
  - 私有属性：\_privateProp

### 2.2 代码质量

- 注释规范：
  - 模块级：描述功能和用途
  - 函数：描述参数和返回值
  - 复杂逻辑：解释关键算法和业务逻辑
- 代码复杂度：
  - 函数长度 ≤ 50 行
  - 嵌套层级 ≤ 4 层
- 错误处理：try-catch

## 3. 版本控制

### 3.1 Git 分支管理

- main/master：主分支（稳定）
- develop：开发分支
- feature/\*：特性分支
- bugfix/\*：修复分支

### 3.2 提交规范

- 格式：`<type>(<scope>): <subject>`
- 类型：feat（新功能）、fix（修复）、docs（文档）、style（样式）、refactor（重构）、chore（构建/依赖）
- 提交信息长度 ≤ 50 字符

### 3.3 .gitignore

- 排除：node\_modules/、dist/、out/、.env 文件、IDE 配置文件、日志文件

## 4. 依赖管理

### 4.1 package.json 配置

- 依赖分类：dependencies（生产）、devDependencies（开发）
- 版本锁定：package-lock.json
- 脚本配置：定义常用脚本（start、build）

### 4.2 依赖选择

- 优先：成熟稳定的库
- 控制数量：避免过度依赖
- 定期更新：使用 npm audit 检查安全漏洞

## 5. 文档管理

### 5.1 项目文档

- README.md：项目概述、安装说明、使用方法
- TODO.md：待办事项和开发计划
- docs/开发日志.md：开发记录

## 6. 安全规范

### 6.1 代码安全

- 输入验证：验证所有用户输入
- 敏感信息：不在代码中硬编码

### 6.2 依赖安全

- 定期扫描：检查依赖漏洞
- 版本管理：及时更新有漏洞的依赖

## 7. 最佳实践

### 7.1 代码组织

- 模块化：拆分为小的可复用模块
- 职责分离：单一职责原则
- 接口设计：清晰接口

### 7.2 项目维护

- 代码清理：定期清理无用代码
- 技术债务：及时解决
- 文档更新：保持同步
